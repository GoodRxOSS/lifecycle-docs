When you have all [starter infrastructure
prerequisites](/docs/setup/prerequisites), use this page to provision GKE or
EKS. The OpenTofu module creates the cluster, supporting services, DNS, and, by
default, Lifecycle itself.

<Callout type="error" emoji="⚠️">
  The starter OpenTofu module creates publicly reachable resources and is
  intended for testing, demos, and learning, not production. Apply applicable
  network policies and identity controls. Your organization must approve these
  security controls.
</Callout>

## Select the installation path

Use this **evaluation and demo path** for a starter cluster. The OpenTofu module
defaults `app_lifecycle_enabled` to `true`. Thus, `tofu apply` creates the
infrastructure and installs the `lifecycle` Helm release. Do not install
Lifecycle a second time with this default path.

An **operator-managed Helm path** needs a supported existing cluster. If you use
the starter module, set `app_lifecycle_enabled = false` before you apply it.
Then, follow [Install Lifecycle](/docs/setup/install-lifecycle).

<Callout type="warning">
  Use these paths for evaluation only. The module pins chart and application
  versions. Before each apply, examine the OpenTofu plan and pinned versions.
</Callout>

Select the cloud provider for the evaluation cluster:

- [Google Cloud Platform (GCP)](#google-cloud-platform)
- [Amazon Web Services (AWS)](#amazon-web-services)

## Google Cloud Platform

### Set up application credentials

```sh
# Select the project.
gcloud config set project <PROJECT_ID>
# Create the application default credentials.
gcloud auth application-default login
```

Enable Kubernetes Engine and Cloud DNS APIs:

```sh
gcloud services enable container.googleapis.com --project=<PROJECT_ID>
gcloud services enable dns.googleapis.com --project=<PROJECT_ID>
```

<Callout type="info" icon={Info}>
  `<PROJECT_ID>` is the Google Cloud project ID, not the project name.
</Callout>

### Bootstrap infrastructure

Clone the infrastructure repository:

```sh
git clone https://github.com/GoodRxOSS/lifecycle-opentofu/
cd lifecycle-opentofu
git checkout b14865912608096379c28ef648f7ed99538b5600
```

Copy the example input file:

```sh
cp example.auto.tfvars secrets.auto.tfvars
```

Example `secrets.auto.tfvars` file:

```hcl secrets.auto.tfvars
gcp_project = "<PROJECT_ID>"
gcp_region  = "<REGION_TO_DEPLOY>"
# this is the default credentials file created by gcloud cli
gcp_credentials_file  = "~/.config/gcloud/application_default_credentials.json"
cluster_provider      = "gke"
dns_provider          = "cloud-dns"     # [cloudflare|route53|cloud-dns]
app_domain            = "<YOUR_DOMAIN>" # e.g. lifecycle.example.org
app_lifecycle_enabled = true            # evaluation path installs Lifecycle
# Required only when dns_provider = "cloudflare":
# cloudflare_api_token = "<CLOUDFLARE_API_TOKEN>"

cluster_name  = "lifecycle-gke" # change this to your preferred cluster name
app_namespace = "lifecycle-app" # chosen namespace for this guide
```

<Callout type="warning">
  When `dns_provider = "cloudflare"`, uncomment `cloudflare_api_token`. Use a
  Cloudflare API token that can manage the selected DNS zone. Keep the token in
  `secrets.auto.tfvars`. The infrastructure repository ignores this file. Do not
  commit it. See the [infrastructure
  revision](https://github.com/GoodRxOSS/lifecycle-opentofu/tree/b14865912608096379c28ef648f7ed99538b5600)
  for the token-scope requirements.
</Callout>

Initialize OpenTofu. Examine the plan. Apply the plan:

```sh
tofu init
tofu plan
tofu apply
```

This creates the Kubernetes cluster, supporting services, DNS records, and,
because `app_lifecycle_enabled` is `true`, the Lifecycle Helm release.

After the apply completes, follow its kubeconfig instructions. Then, test the
sample application:

```sh
curl -v "https://kuard.<YOUR_DOMAIN>"
```

See the example [apply
output](https://github.com/GoodRxOSS/lifecycle-opentofu/blob/b14865912608096379c28ef648f7ed99538b5600/README.md#4-initialize--apply)
for more kubeconfig details. Continue to [test the evaluation
installation](#test-the-evaluation-installation). Do not run a second Helm
installation.

## Amazon Web Services

```sh
# Configure the evaluation profile
aws configure --profile lifecycle-oss-eks
AWS Access Key ID [***]: <key id, or enter>
AWS Secret Access Key [***]: <secret key, or enter>
Default Region name: <region, or enter>
Default output format: <format, or enter>
```

<Callout type="warning">
  The AWS evaluation procedure uses `AdministratorAccess`. Limit that access to
  an isolated evaluation account. Remove the access when the test ends. Use
  approved least-privilege permissions for an operator-managed deployment.
</Callout>

## Test the evaluation installation

Use the same namespace and host values supplied to OpenTofu:

```sh
export LIFECYCLE_NAMESPACE="<app_namespace>"
export LIFECYCLE_APP_HOST="<app_subdomain>.<app_domain>"

kubectl get deployments,pods --namespace "$LIFECYCLE_NAMESPACE"
curl --fail --head "https://${LIFECYCLE_APP_HOST}"
```

Wait for the Lifecycle deployments. Make sure that the HTTPS endpoint responds.
If the module's pinned release fails, examine the OpenTofu and Kubernetes output.
Do not add a second Helm release.

Then, [create and connect the GitHub App](/docs/setup/create-github-app).
