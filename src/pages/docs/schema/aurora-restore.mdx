The `auroraRestore` Service makes an AWS Aurora copy for an ephemeral
Environment. It uses the latest restorable time of a tagged source cluster.

An operator must enable Aurora restore and configure its AWS credentials, region,
network, engine, and instance values. You cannot supply these installation
settings in `lifecycle.yaml`. If Aurora restore is not available, ask your
operator to configure it.

## Required fields

| Field       | Type   | Description                                       |
| ----------- | ------ | ------------------------------------------------- |
| `command`   | string | Path to the built-in Aurora helper.               |
| `arguments` | string | Source-tag and cost-attribution helper arguments. |

```yaml filename="lifecycle.yaml"
services:
  - name: "database-copy"
    auroraRestore:
      command: "scripts/aurora-helper.ts"
      arguments: "--sourceTagKey restore-for --sourceTagValue preview-source --appShort payments"
```

## How it works

1. Lifecycle finds Aurora clusters that match the source tag.
2. Lifecycle selects the matching cluster with the latest creation time.
3. Lifecycle makes a copy at the latest restorable time.
4. Lifecycle makes an Aurora instance for the new cluster.
5. Lifecycle makes the cluster endpoint available to other Services.

Put only source selection and `appShort` arguments in `arguments`.

## Example

```yaml filename="lifecycle.yaml"
environment:
  defaultServices:
    - name: "api"
    - name: "aurora-db"

services:
  - name: "api"
    github:
      repository: "myorg/api"
      branchName: "main"
      docker:
        defaultTag: "main"
        app:
          dockerfilePath: "Dockerfile"
          env:
            DATABASE_URL: "{{aurora-db_internalHostname}}:5432"
          ports:
            - 3000

  - name: "aurora-db"
    auroraRestore:
      command: "scripts/aurora-helper.ts"
      arguments: "--sourceTagKey restore-for --sourceTagValue preview-source --appShort payments"
```

## Typical tasks

- Test changes against representative data.
- Test database migrations against a representative schema.
- Reproduce a defect that depends on database state.

<Callout type="warning">
  Source data can contain sensitive information. Before you make a copy, apply
  your necessary data controls and access limits.
</Callout>

## Teardown behavior

Lifecycle deletes the copied instance and cluster during Environment teardown.

<Callout type="warning">
  Teardown does not create a final snapshot. Do not put unique or durable data
  in the copied cluster.
</Callout>

Other Services can read the Aurora Service template variables after the cluster
is ready.
